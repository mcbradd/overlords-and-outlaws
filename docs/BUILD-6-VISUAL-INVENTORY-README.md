## What counts

Baseline rows cross every literal state with all 21 dimensions. Each execution records the exact candidate, served assets, fixture or action path, actual viewport/profile, assertions, screenshot/recording path and hash. Every visual opening has reviewer, tool, timestamp, displayed scale/crop and verdict. Operative text/ranks require native readable views or explicit native-pixel crops. Downscaled views may establish composition defects but cannot pass small-text readability.

The 168 intrinsic assets comprise 52 original portraits, 52 live faces, 52 reference faces and 12 shared components/font samples/aids. IDs are stable references to the selected content/renderer; implementation must resolve each to its actual source or generated file/hash. Reviewing an intrinsic asset does not approve every rendered context. Retained historical assets/screens remain covered by their existing complete release contracts and B612/B613; this core inventory does not erase them.

Keep the required denominator fixed when capture fails. Missing, failed, mismatched, uninspected and limited rows remain distinct from accepted rows. New screenshots do not inherit an earlier review. Intrinsic asset review counts are separate from screen/profile row counts; repeated crops do not inflate coverage.
